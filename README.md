# TIME TO DIE 💀

Telegram Mini App по мотивам фильма **«Countdown» (2019)** — того самого, где
приложение показывало, сколько тебе осталось жить. Вводишь имя и дату рождения,
приложение «сканирует» тебя, подключается к Реестру судеб и выдаёт **точную дату
и время смерти** с обратным отсчётом.

Чистый HTML/CSS/JS в одном файле. Без бэкенда, без сети, без зависимостей
(только `telegram-web-app.js` и два Google-шрифта).

> Технически: все предсказания генерируются детерминированным алгоритмом
> целиком на клиенте. Никаких серверов, никаких внешних данных.

---

## Как это выглядит

| Этап | Что происходит |
|---|---|
| **Boot** | Чёрный экран, логотип с глитчем, фейковые строки загрузки Реестра, внизу `made tengizka` |
| **Анкета** | Бейдж привязанного аккаунта, имя (подтягивается из Telegram) + дата рождения через собственный пикер-барабан |
| **Соглашение** | Модалка с 11 пунктами «пользовательского соглашения», которые нельзя не принять |
| **Сканирование** | ~8 секунд: вращающиеся кольца, проценты, консольный лог, низкий дрон, сердцебиение, которое ускоряется. На 55% лицо мелькает сублиминально, на 86% — полноценный скример |
| **Вердикт** | Дата и время смерти, причина обрыва, живой таймер `дни / часы : минуты : секунды`, шкала прожитой жизни, 10+ карточек статистики, процентиль среди других людей, «особые отметки» |
| **ВРЕМЯ ВЫШЛО** | Экран со «статикой», если срок, выданный аккаунту, уже истёк. Обжалованию не подлежит |

## Как считается дата

**Вердикт привязан к аккаунту Telegram.** Идентификатор субъекта —
`TG#<user.id>` из `initDataUnsafe.user`. Имя и дата рождения в анкете на срок
**не влияют** вовсе: они нужны только для обращения и для шкалы «прожито %».
Сменить дату рождения и вытянуть новый срок не получится.

Вне Telegram (обычный браузер) идентификатор собирается из имени и даты —
`GUEST#<имя>#<дата>`, чтобы приложение оставалось детерминированным и там.

Дальше `xmur3(соль + идентификатор)` → `mulberry32`, и из сида тянется остаток
жизни. Разброс намеренно дикий — от нескольких дней до ста лет:

| Остаток | Доля аккаунтов |
|---|---|
| 1–5 дней | ~6% |
| до месяца | ~8% |
| 1–6 месяцев | ~10% |
| до 2 лет | ~12% |
| 2–10 лет | ~16% |
| 10–30 лет | ~18% |
| 30–55 лет | ~18% |
| 55–75 лет | ~9% |
| 75–100 лет | ~3% |

Среднее — около 20 лет. Время смерти смещено к «ведьмину часу» (03:00–05:59).

### Исключения Реестра

Массив `OVERRIDES` в `index.html` — персональные записи, выданные вручную в
обход общего распределения:

```js
var OVERRIDES = [
  { u:'golfcartowner', years:282 }
];
```

Матчинг по `username` (поле `u`, регистр не важен) или по числовому `id`
(поле `id`). Для такого субъекта:

- остаток фиксируется как `ceil(years * 365.2425) + 1` дней от полуночи дня
  первого сканирования (`+1` компенсирует округление вниз по времени суток,
  чтобы крупное число показывало ровно заказанные годы);
- крупное число вердикта переключается в режим лет: **«282 ГОДА · 102 999 ДНЕЙ»**
  (порог — 100 лет остатка, у остальных по-прежнему дни);
- процентиль принудительно `0`: «Твой срок короче, чем у 0% людей… Оставшиеся
  100% уйдут раньше тебя»;
- метка срока `АНОМАЛИЯ` и широкая карточка «ИСКЛЮЧЕНИЕ ИЗ РЕЕСТРА: срок 282
  года превышает все расчётные пределы. Реестр не может это объяснить.»;
- запись в хранилище помечается `ov:true`. Исключение перебивает даже уже
  замороженный вердикт: если у субъекта найдена старая запись без метки,
  она пересоздаётся под исключение при следующем запуске.

Причина смерти, отметки и точное время для исключения тянутся из того же
сида, что и у всех, — персональной является только длина срока.

Из одного сида работают **два независимых потока**: один считает дату, второй —
причину, процентиль и особые отметки. Поэтому при повторном открытии всё
совпадает байт в байт, даже если дата берётся из хранилища, а не пересчитывается.

Дата замораживается в `localStorage` (ключ `ttd_registry_v3`, запись на каждый
идентификатор) в момент первого запроса — иначе отсчёт не тикал бы, а стоял на
месте.

**Путь назад закрыт.** Кнопок возврата нет вовсе: ни «К анкете», ни
«Пересканировать», ни «АНКЕТА» в шапке. Как только у аккаунта появилась запись,
`route()` на старте идёт сразу в `openExisting()` — любой последующий запуск
открывает уже вынесенный вердикт со всей информацией, минуя анкету, соглашение
и сканирование. На вердикте висит плакат «ПУТЬ НАЗАД ЗАКРЫТ · Реестр не
пересматривает решения. Анкета уничтожена.», а шапка при повторном запуске
пишет «вердикт найден. возврат невозможен». Если срок истёк — сразу экран
«ВРЕМЯ ВЫШЛО» без единой кнопки выхода. Сбросить можно только вручную,
очистив `localStorage` (ключ `ttd_registry_v3`).


## Пасхалки

- **13 тапов по таймеру** — скример и сообщение «ТЫ НЕ МОЖЕШЬ ЭТО ИЗМЕНИТЬ»
  (в правом нижнем углу виден счётчик).
- **Редкая причина смерти** — Ожин (демон из фильма), ~3% субъектов.
- **Пункт 11 соглашения**: «Реестр не несёт ответственности за совпадения.
  Совпадений не бывает.»
- **Служебных кнопок нет вовсе**: ни звука, ни фуллскрина, ни возврата.
  Интерфейс чистый, звук выключается только вместе с приложением.

## 1. Залить на GitHub Pages

```bash
git add index.html README.md
git commit -m "TIME TO DIE: telegram mini app"
git push
```

Дальше в репозитории: **Settings → Pages → Deploy from a branch → `main`, `/ (root)`**.
Через минуту появится публичный HTTPS-адрес вида
`https://<твой_логин>.github.io/<репозиторий>/` — именно он нужен Telegram.

## 2. Подключить как Telegram Mini App

Приложение работает в **full-size**: на старте вызывается
`requestFullscreen()` (Bot API 8.0), и Mini App разворачивается в полноценный
полноэкранный режим без шапки Telegram — в портрете и ландшафте. Часть
клиентов разрешает фуллскрин только по пользовательскому жесту, поэтому
попытка повторяется на первом касании. Видимых кнопок-переключателей нет —
интерфейс остаётся чистым. Если клиент старый и
метода нет — всё аккуратно деградирует до обычного `expand()`.

Отступы под вырезы и домашний индикатор берутся из `tg.safeAreaInset` /
`contentSafeAreaInset` и раскладываются в CSS-переменные `--sa-*`, а в разметке
используются через `max(env(safe-area-inset-*), var(--sa-*))`, чтобы не
задваивать в браузере и не терять в Telegram. Слежатся события
`fullscreenChanged`, `safeAreaChanged`, `contentSafeAreaChanged`,
`fullscreenFailed`.

1. **@BotFather** → `/newbot` (если бота ещё нет).
2. `/newapp` или `/mybots` → бот → **Bot Settings → Menu Button**.
3. В **Web App URL** вставь ссылку с GitHub Pages.
4. `/setmenubutton` — та же ссылка, чтобы приложение открывалось по кнопке меню.
5. Иконку лучше брать тёмную с красным таймером — вписывается в тему.

Приложение само вызывает `ready()`, `expand()`, красит шапку и фон в `#040404`,
использует `HapticFeedback` для вибрации на скримерах и подтягивает имя из
`initDataUnsafe.user`. В обычном браузере всё это аккуратно деградирует.

## 3. Локальный запуск

```bash
python3 -m http.server 8080
# → http://localhost:8080
```

## Настроить под себя

Всё правится в `<script>` внутри `index.html`:

| Что | Где |
|---|---|
| Причины смерти (~50 шт.) | массив `CAUSES` |
| «Особые отметки» с подстановкой `%Y` `%M` `%D` | массив `WARNINGS` |
| Пункты соглашения | массив `EULA` |
| Строки сканирования | `SCAN_LOGS`, этапы — `SCAN_STAGES` |
| Длительность скана | `var dur = 8200` в `startScan()` |
| Дикий рандом срока | массив `SPANS` (доли и диапазоны в днях) |
| Привязка к аккаунту | `subjectIdentity()` — `TG#<user.id>` |
| Скример на 86% | `if(!scared && prog >= 86)` |
| Сублиминал на 55% | `if(!subbed && prog >= 55)` → `subFlash()` |
| Анатомия скримера | `scare()`, `scream()`, слои `#scare` |

**Анатомия скримера.** Удар поставлен в три такта: (1) чёрная пауза ~110 мс —
дрон обрывается в ноль, тишина бьёт сильнее звука; (2) сам удар ~620 мс:
гротескное лицо (свой SVG, `feTurbulence` + `feDisplacementMap` для варпа)
влетает с масштаба 3.4x в трёх хроматических слоях (красный/циан/основа,
`mix-blend-mode:screen`), поверх — строб-вспышки, катящиеся тёмные полосы,
статика и тряска всей сцены; звук — слоёный крик (шумовой шриек 3200→320 Гц,
две расстроенные пилы вниз, суб-бум, диссонансный кластер) плюс три такта
вибрации; (3) у ~30% случаев — второй слабый удар вдогонку через случайные
0.3–0.7 с, когда человек уже выдохнул. На 55% сканирования то же лицо мелькает
на 110 мс с прозрачностью 7% — на грани восприятия, чтобы к основному удару
мозг уже был встревожен непонятно чем.
| Палитра | переменные `:root` вверху `<style>` |
| Хранилище вердиктов | `LS_KEY` |
| Подпись на заставке | `.splash-foot` в разметке и в стилях |
| Пикер даты (барабаны) | блок `CUSTOM DATE PICKER`: `DP_H`, `YEAR_MIN`, `dpS` |
| Крещендо на скане | `droneLevel(p)`, `riserStart(ms)`, переменная `intensity` |
| Мрачный эмбиент | `ambientStart()`, `motif()`, `scheduleMotif()` |
| Озвучка барабана даты | `wheelTick()`, `wheelThud()`, `bump()`, `boom()` |

**Статичный layout.** Документ не скроллится вообще (`html,body{overflow:hidden}`,
`body{position:fixed}`) — как в нативном мини-аппе. Прокручивается только сам
активный экран внутри себя (`.screen{overflow-y:auto}`), со скрытым скроллбаром
и `overscroll-behavior:contain`, так что никаких резиновых отскоков и езды
«туда-сюда». Экраны сканирования и «ВРЕМЯ ВЫШЛО» центрируются через
`margin:auto`, когда хватает места, и честно скроллятся, когда нет.

**Звук с первой секунды.** AudioContext создаётся ещё на заставке (до первого
жеста он suspended — браузеры иначе не дают), поэтому эмбиент бьёт в ту же
миллисекунду, как пользователь коснулся экрана: низкий дрон + расстроенный
кластер на малой секунде и изредка далёкий колокольчик (`motif`). Дальше всё
накачивается: на скане дрон/фильтр/LFO и сердцебиение растут с прогрессом,
с 66% вступает райзер, на 100% пик 0.85 и release в 0.3 на вердикте.
Барабан даты озвучен полностью: щелчок-детент на каждое деление (разная высота
для дня/месяца/года), глухой удар каждые три деления с вибрацией, boom на
открытии и тяжёлый стингер на подтверждении; пока пикер открыт, дрон держится
на повышенном напряжении 0.42.

Нативный `<input type="date">` не используется вовсе: на iOS он открывает
системную светлую вертушку, которая ломает всю атмосферу. Вместо него —
собственный пикер-барабан (день / месяц / год) на `scroll-snap`, с красным
курсором, крупным считыванием сверху и фейдами по краям. Выбранное значение
хранится в `birthValue`, а не в DOM-инпуте.

Звук целиком синтезируется через WebAudio (дрон, сердцебиение, колокол,
скример-шум) — никаких внешних файлов. Он стартует только после первого
тапа, как и требуют браузеры.

Анимации уважают `prefers-reduced-motion`: вспышки и скример отключаются,
если у пользователя включён щадящий режим.
